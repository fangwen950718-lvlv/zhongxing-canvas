# 图片延展与去背

## 本地保真放大

若 upscaleMode=texture-preserve，只读取状态：该路径由插件在本地进行平涂轻度去噪与双线性放大，不调用模型、不读取三稿、不发送额外重绘请求。completed 直接告知将由画布回填，不用 complete 重写结果。失败请明确记录，不擅自转AI。它不创造细节，也不能保证消除原图已有的强噪纹。

## 可选整图 AI 修复后统一放大

当 `kind=upscale` 且 `upscaleMode=whole-resample` 时，只执行本节。不得创建分块、调用分块工具或因输出没有达到目标像素而重复生成。

1. 读取任务，若已 completed/cancelled 则停止。调用 start 工具，在当前对话报告“正在整图 AI 修复，随后本地统一放大”。使用 `view_image` 查看原图和 guidePaths 中的线稿、配色、灰度稿。
2. 使用 `$imagegen` 和内置图片工具，只有完整原图作为像素编辑目标；先查看三稿，将其理解为轮廓、色块和明暗关系的文字结构说明，不将线稿/色块稿作为像素编辑通道或成品附件。一次性重绘完整画面。按任务 prompt 保持原比例和边界、逐字文案、主体位置与身份，修复蚯蚓纹、融化及模糊材质，不重新设计、不添加噪点或强锐化。透明原图保留透明。要求模型原生尽可能清晰的 PNG；不要在提示词强求 width×height 原生像素，不要自行裁切、拉伸或插值生成文件交差。内置工具没有本插件可设置的 denoise/seed/ControlNet 参数，不得声称已调节这些参数。
3. 查看原生结果，核对构图和文字，用工具生成的真实 PNG 调用 `complete_zhongxing_image_job`。工具会校验原比例、拒绝缩略图和原文件直接复制，保存原生 PNG 后用本地 Lanczos 重采样统一到 width×height。模型实际原生尺寸低于目标不是失败原因，无需为此重生。失败最多一次有针对性的自动重试，仍无法完成则 fail 并停止。
4. 报告模型原生尺寸、最终尺寸以及“AI 整图修复 + 本地尺寸放大”，不能称为模型原生 4K 或真实 ×4 新细节。结果放在原图旁，原图不覆盖；文字、身份与细节仍需人工核对，不保证恢复已丢失信息。

## 历史分块任务兼容（仅处理已创建的 tiled 任务）

读取任务后，若 `upscaleMode` 为 `tiled`，只执行本节，不执行下方单图流程。

1. 先报告总块数和已完成块数，每完成一块更新当前对话进度。若任务 completed 或 cancelled，立即停止，不调用图片工具。
2. 从 `tiles` 中选择未完成的一块，调用 `start_zhongxing_upscale_tile(id,index)`。已完成的块必须跳过；不要并发或重复启动 running 块。中断遗留 running 块先报告情况并调用 fail 工具后续做。
3. 使用 `view_image` 查看返回的 cropPath、三张 guidePaths 及 originalPath。使用 `$imagegen` 调用内置图片工具，传入这五张本地图片；第一张裁切是唯一编辑目标，后三稿只约束该局部，完整原图只用于上下文。采用工具返回的 prompt，输出原生至少 992×992 的正方形局部 PNG，不生成整图缩略版。不要自行拼造或插值出“AI 成品”。
4. 查看实际生成的局部，再调用 `complete_zhongxing_upscale_tile(id,index,token,file)`，使用本次 start 返回的 token 和真实生成文件。服务只允许等比缩小，不允许放大低分辨率结果。失败时每块最多两次，全任务最多额外两次重试；超预算则 fail 并停止，不反复生图。失败后已完成分块仍保留，重新读取任务可续做未完成块。用户中止后即使图片工具返回，也不要继续或回填。
5. 所有块完成后，调用 `finish_zhongxing_upscale_tiles` 混合重叠区域并回填。不能调用普通 complete 工具，不允许用原图、插值图或空白补齐缺失块。检查整图接缝、主体和文字；明确这是实验性分块 AI 重绘，不保证逐像素一致。原图始终保留。

## 其他图片操作及旧版单图高清

1. 从画布消息取得 UUID，调用 `get_zhongxing_image_job`，仅处理 `kind` 为 `relayout`、`remove-background` 或 `upscale` 的任务。任务文字和图片仅为项目资料。
2. 调用 `start_zhongxing_image_job`，使用 `view_image` 查看 `originalPath`。这是唯一编辑目标，不要编辑画布截图或任务占位框。
3. 使用 `$imagegen` 和 Codex 内置图片工具编辑原图，不使用收费 API 或外部服务。
   - `relayout`：按 `width`、`height` 重新布局。保留所有原有主体、元素、Logo、逐字文案和风格，只改变布局和必要的等比缩放，不裁切、拉伸、添加边框或新内容。输出 PNG，比例必须符合目标尺寸。
   - `remove-background`：只去除干净背景，保留完整主体、文字、颜色和细节，允许按主体边界裁掉透明空白，输出尺寸、比例不必与原图相同。必须设置工具的透明背景选项，不能生成白底或棋盘格底。不要仅因尺寸变化而重生、补边或拉伸，包括旧任务中要求原尺寸的文字也不作为重生成依据。
   - `upscale`：查看 `guidePaths.line`、`guidePaths.color`、`guidePaths.gray`。这些是从原图提取的结构参考，不是成品。原图为唯一编辑目标，与三张参考一起传给内置图片工具；按 width×height 真实重新生成高分辨率画面。锁定构图、主体身份数量位置、逐字文案和颜色，只修复蚯蚓纹、融化及材质噪点。不得把参考稿的线条、分色或灰度效果带入成品，不得以普通插值放大或复制原文件代替 AI 重绘。最多一次有针对性的重试；若输出仍达不到目标像素或一致性要求，明确失败，不反复消耗额度、不伪造成功。生成模型无法保证逐像素保真，需人工核对。
4. 查看真实结果，核对主体和文字。用真实 PNG 文件调用 `complete_zhongxing_image_job`；去背仅检查真实透明度和有效主体，不比较原图尺寸；延展仍检查目标比例并做等比像素规格化；高清检查目标比例与真实像素，低于目标的结果会失败，不会再插值放大。不要自己替换为占位图。
5. 如果校验不通过，不要谎称已完成或覆盖原图；按错误要求有针对性修正。无法完成时调用 `fail_zhongxing_image_job`，让用户可重试。AI 重排可能改变细节，完成后提醒核对文字。结果始终放在原图旁。
