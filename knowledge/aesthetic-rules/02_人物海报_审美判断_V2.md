# 人物海报审美判断 V2

用途：供众行无限画布生成人物海报方案与含文字排版的完整 demo 提示词。核心是人物呈现准确、动作可信、图文稳定，而非强制简洁棚拍。版本日期：2026-10-26。


## 导入与使用说明

用本文件完整替换对应分类的旧正文，不把V1与V2叠加；若上传后新增了规则库，需要选择该V2规则库才会生效。只替换分类正文不会自动更改通用底层规则，文中的兼容建议需在通用规则编辑区同步处理。兼容检查依据已安装插件2.2.0-local.5的默认通用规则，不代表已读取各项目自行保存的规则快照。

正文是执行规则，示例和文末案例是理解材料。实际任务只使用当前brief及其真实附件；不得把示例品牌、文案、角色、尺寸、场景或案例中的事实带入客户项目，也不要求每次复用示例的三种风格。文末参考不属于成图文字，不应全部塞进每次方案或提示词。

## 1. 分类边界与任务约定

人物海报是一种表现形式，可以用于官宣、访谈、品牌态度、产品广告等用途。只执行当前人物类别与 brief 明确给出的业务要求，不自动调用其他类别：未提出卖货时不加产品bar、价格和购买按钮；提出代言产品时则按 brief 保留对应产品与文案，不因为“人物为主”而删掉它们。

人物身份、脸部结构、关键动作和自然身体比例是准确性底线。提供形象照片时，默认尽量保持同一姿态，包括头部角度、肩线、手位、坐站方式、视线和身体朝向；不要为了三组差异自行让人物跑跳、转身、换侧脸。优先变化环境、图形组织、色彩与文字关系。只有 brief 明确允许时才设计新动作。

实际进入生图任务的参考照片才具约束作用；提示词里提到文件名并不等于模型已经得到图片。素材不在任务中时，应说明“待补人物参考图，当前仅验证构图”，不得声称身份已锁定。单张正面照不能提供可靠的背面、侧面或复杂运动细节。相似度与畸变需要看实际结果核对，不能承诺文字指令能百分之百保真。

每次恰好三组 options，每组含简短 title、1—2句 proposal、4—8组 label/content sections 和独立完整的中文 imagePrompt。sections 可用人物保留项、概念、构图、文字、色光、素材风险。无场景时不强分前中后景。已有标题、姓名、身份、日期不得擅改或补造；原创标题标明“建议文案”。没有Logo素材时只使用确认的品牌文字署名。

## 2. 参考规律及适用解释

- 人物轮廓与标题形成大结构。近景正面人像常用头肩轮廓托住上方或下方标题；不能因为要突出文字就把字穿过眼睛、鼻子和嘴。
- 框景能够组织复杂内容。唱片套、窗框、画框、票据或色块条带能把人物与文字变成一个整体，但框必须与主题有关系，不为填空层层套框。
- 场景可以讲述人物处境。金色布幕、城市空间、车辆、舞台或山水能交代关系与气质；人物仍需要在局部明度、轮廓和尺度上清晰。
- 多人画面的稳定来自主次和关系。车上群像、访谈嘉宾阵列、双人对望分别依靠空间支撑、网格和视线组织，不必把所有脸做得一样大，也不能凭模型喜好打乱客户确定的排序。
- 摄影与图形、绘画可以混合。摄影人物叠在绘画花卉或纯色条带上，关键在于分层边缘、综合色彩与清晰图文关系，不是把真人也渲染成塑料角色。
- 系列海报常固定人物尺度、标题位置和色彩系统。既能保持活动识别，也能容纳不同嘉宾；固定项不应迫使原照片姿态大幅改变。

影视、综艺参考只用来学习人物、图文和场景的组织，不自动继承演职员表、平台Logo、档期、戏剧化亲密关系或悬疑道具。

## 3. 先锁素材，再做创意

1. 读 brief，确认单人/双人/多人、用途、尺寸、确定文字和不可改素材。姓名、职务、代言关系只使用客户提供的信息。
2. 列出可见保留项：脸型、五官间距、发型、年龄感、头肩方向、手与道具、衣服关键细节。不得从模糊照片推断不可见细节。
3. 将人物视线与身体方向画成简单的视觉路径。朝右的人适合在其右侧留出呼吸或回应空间；不能为迁就版式擅自镜像人物，尤其衣服文字、痣、手持物和品牌标识会随之出错。
4. 先放人物轮廓和标题组，再安排背景与道具。近景脸部周边降低细节，手部周边不加难分辨的小物；完整肢体所需空间不足时扩大画布或调整人物整体尺度。
5. 用主题选择一种图形/场景机制，再统一色光。三组差异应来自人物与空间或文字的关系，不依靠改变同一个人的脸与姿态。
6. 分开检查身份、身体、空间支撑和排版，任一准确性问题未过都不能用“氛围好”抵消。

## 4. 可执行构图与排版规则

| 条件 | 具体动作 | 判断标准 |
|---|---|---|
| 单人近景、官宣或身份识别 | 保留原头部角度，把标题放在面部以外的连续区域，姓名与身份相邻 | 先认人，再找到姓名；眼睛与口鼻没有穿字 |
| 半身/全身、有明确姿态 | 人物保留原比例整体缩放，以负空间承字，不分别拉长腿或压缩上身 | 身体重心、关节和画面支撑成立 |
| 双人关系 | 按原素材安排视线、朝向和距离；用共同背景或一条图形路径连接 | 两人处于同一空间，头部大小与距离逻辑一致 |
| 多嘉宾、信息密集 | 使用统一裁切框、姓名基线与图文间距；主次与排序服从 brief | 每个人可辨，名字不会错配或被裁掉 |
| 人物与巨大主题字结合 | 把人物置于字前或字后明确一层，保持主体词可辨；避免细笔画跨脸 | 缩小后读得出字，也认得出脸 |
| 概念场景或拼贴 | 用单一框景、透视或视觉路径组织，降低脸周围的细节对比 | 人物不是贴上去的孤岛，概念不盖过身份 |

切边需要有意图。允许自然的胸像、半身裁切，但避免在手指、手腕、膝盖等关节处生硬截断；不是所有近景都必须保留全身。若原照片手在画外，不为“完整”凭空重造复杂手势。

人脸被复杂背景淹没时，先调整背景明度与细节，再考虑轻微轮廓光；不要给人物套一圈厚白边当作统一补救。若采用明确的纸面拼贴，切边应与整套图形语言一致。

标题按语义断行。姓名、职务和主标题建立大小差异，人物姓名不是每次都必须最大。对于已经确定的长标题，优先调整字块宽度、行数及留白，不能删词、压扁字或把每一行做成不同字体。日期、地点等仅在 brief 确认后出现。

Logo与署名落在稳定区域，避开头顶紧贴、肩线相切和衣服标识混淆。人物头顶、标题底边与Logo之间需要明确间距；“几乎碰到”往往比真正重叠更不稳定。

## 5. 人物准确性、色光与质感

### 人物保留项

- 脸：保持原图的脸型、五官相对位置、年龄感和自然不对称，不自动大眼、尖下巴、缩鼻、换笑容。
- 头发与衣物：发际线、分缝、刘海、主要长度和服饰轮廓保持；不要把耳饰、衣领或袖口融合进皮肤。
- 手与道具：检查手指数量与关节方向、握持接触、道具遮挡次序。原手势复杂时优先保留原素材，避免重新生成。
- 身体：检查肩颈连接、左右肢体、坐姿受力和双腿方向。人物整体同比例缩放，不能独立修长身体局部来“显高”。
- 多人：每人各绑定自己的参考图，不混脸，不复制同一张脸，不互换服装与姓名。

### 光线与摄影质感

有照片时先适配原图主光方向与软硬程度，再设计背景。不能只在提示词写“逆光大片”就要求原图正面硬光自动消失。优先改背景或用可解释的辅助光统一环境；身份保持与大幅重打光发生冲突时，优先减少改动。

保留自然皮肤纹理与适度肤色变化，避免塑料高光、过度磨皮、假毛孔和面部脏噪点。人物可以身处强色光场景，但眼睛、肤色与表情仍应可辨。不要用整体高饱和度覆盖不同人的肤色，也不要把黑发和深色衣服压成一块。

摄影人物配绘画背景时，允许两种媒介明确并置，不必伪装成写实合成；若要求真实同场摄影，则透视、阴影和色温必须统一。只能选择与方案相符的一套逻辑，不能同时要求无缝写实和随意贴纸感。

## 6. 提示词必须写出的内容

先写实际参考素材的用途与保留项，再写画幅、人物位置、原姿态与视线、背景机制、标题断行与姓名归属、色光材质和避免项。镜头描述服从原照片：近景照片不能在不补足依据时要求变成低机位全身仰拍。

“保持同一个人”必须展开为脸部、发型、原姿态、手位、服装等具体约束；“不要畸变”必须展开为该画面最可能出现的接触与遮挡问题。负面描述只列相关风险，不堆砌互相矛盾的禁词。

完整海报要求文字实际呈现。提示词逐字列出标题、姓名、身份与署名，并说明位置和层级；品牌标识使用已附素材原比例。生成后仍需核对相似度、错字和肢体，必要时保留原人物图层，仅修背景与排版。

## 7. 三组完整示例

虚构 brief：访谈品牌“见面”制作3:4单人海报。示例假定已附一张经客户确认的人物照片：成年嘉宾林禾，灰色上衣，身体正面、坐姿，头轻微朝画面右侧，双手自然搭在膝上。确定标题“每一种认真，都值得被看见。”；姓名“林禾”；身份“本期对谈嘉宾”；署名“见面”。不提供日期、场地和图形Logo。以下三组均保持原姿态。

### OP1｜在一束光里

**proposal：** 以一块平静的光区集中注意，让嘉宾的神情和标题共同表达对认真生活者的关注。

**sections：**
- 人物保留：原脸、发型、灰色上衣、坐姿、头向与膝上双手不变。
- 构图：人物位于右侧，保留座椅支撑，左上留整块承字墙面。
- 场景：素色真实室内，以原照片光向决定亮部。
- 文字：标题三行左对齐，姓名与身份成组，署名在底部。
- 色光：暖灰、浅米色，柔和照明与真实皮肤质感。
- 风险：不把原有坐姿变成站姿，不把手藏进阴影掩盖错误。

**imagePrompt：** 使用实际附入的人物照片制作3:4竖版完整访谈海报。保留照片中林禾的脸型、五官位置、发型、灰色上衣、正面坐姿、头轻微朝画面右侧的角度，以及双手自然搭在膝上的位置，不换表情、不镜像、不改变身体比例。人物整体放在右侧，座椅与地面接触可信，头、手和膝部有完整空间。背景是暖灰与浅米色的安静真实室内，照明方向和柔和程度适配参考照片，保留自然肤质。左上用深灰清晰中文中黑体排三行：“每一种认真，”／“都值得”／“被看见。”，不压脸、头发和双手；左中下写姓名“林禾”，下接小号“本期对谈嘉宾”；左下小字“见面”。只有这些文字，不加日期、地址、赞助标识和图形Logo。标题、姓名与署名共用左边线，不用描边光字，不增加新手势或道具。

### OP2｜一扇向外的窗

**proposal：** 用一个明确的窗框将人物与外部世界联系起来，保留原照片姿态，增加开放而非封闭的对谈氛围。

**sections：**
- 人物保留：与OP1相同的身份及原姿态，不因窗景改变头向。
- 场景：真实空间中的大窗，窗外树影只交代环境。
- 构图：人物居中偏下，窗框围合但不穿头，文字在左上实墙。
- 文字：主标题两行，姓名身份在右下，署名左下。
- 色光：灰绿窗外与米白内墙，延续照片原主光。
- 风险：树枝不长在头后，窗沿不横切脖子，双手不增删。

**imagePrompt：** 制作3:4竖版完整人物访谈海报，使用已附林禾照片，严格保留原五官、发型、灰色上衣、正面坐姿、轻微向画面右侧的头向、原表情与膝上双手。人物置于中央偏下，保持原照片视角与比例。构建真实室内窗景：人物后方一个宽阔简洁的窗框，窗外灰绿色树影低对比，左上是米白实墙；窗框不穿过头部、脖子或双手，树枝远离脸部轮廓。人物与环境照明适配参考图主光，不重塑脸部。左上实墙用深墨绿色中文印刷字体排两行标题：“每一种认真，”／“都值得被看见。”，保持清晰且不跨人物；右下小组写“林禾”与“本期对谈嘉宾”；左下署名“见面”。文字组都有明确边距，姓名与人物归属清楚，不生成窗贴文字、额外嘉宾、日期和图形Logo，不改变坐姿或给人物新增物件。

### OP3｜认真有自己的形状

**proposal：** 用纸面几何图形组织人物与标题，把“认真”表现为清晰、有秩序的版面，区别于前两组真实空间。

**sections：**
- 人物保留：原人物照片清晰抠出，保持原姿态与原比例。
- 媒介：摄影与平面纸色块明确并置，不伪装写实空间。
- 构图：人物在左下完整成组，右上大字形成视觉平衡。
- 文字：标题三行右上左对齐，姓名身份置于人物旁的独立标签区。
- 色彩：奶油白、钴蓝、少量暖橙，照片肤色保持自然。
- 风险：图形不切脸，不用粗白边，纸面阴影不污染照片。

**imagePrompt：** 生成3:4竖版完整访谈海报，采用摄影人物与平面纸张图形组合。将已附照片中的林禾按原比例整体置于左下，保留原脸、发型、灰色上衣、正面坐姿、头轻微向画面右侧、双手搭膝的姿态，保留座椅，不重新设计肢体。奶油白底，人物后方一块钴蓝色矩形组织轮廓，右侧仅一条暖橙色窄纸条作平衡，边缘干净，不做三维舞台。右上标题三行左对齐：“每一种认真，”／“都值得”／“被看见。”，深蓝中黑体，标题整块不压到脸或头发。人物旁独立浅色标签写“林禾”，下一行“本期对谈嘉宾”；底部署名“见面”。保留照片自然肤色，纸图形只有轻微统一阴影，不给人物加厚白边，不生成新表情、新手指、额外文字或图形Logo。

## 8. 反例、修正与否决项

| 问题 | 修正动作 | 通过标准 |
|---|---|---|
| 三组人物各长一张脸 | 固定同一参考图和保留项，减少重打光与重绘 | 与参考图逐项比对身份特征 |
| 原照片坐姿被改成跑跳 | 收回新动作，改变场景或图形机制 | 头向、肩线、手位与坐站关系保留 |
| 手与衣服融合、道具悬空 | 简化交互，保留原手，明确前后遮挡与接触 | 手指结构及握持可信 |
| 大字压住五官 | 移动文字组或人物整体位置 | 眼、鼻、嘴无遮挡，主标题仍完整 |
| 人像像贴在背景上 | 真实方案统一透视与光色；拼贴方案统一边缘语言 | 媒介逻辑清晰，人物有支撑 |
| 多人脸重复或姓名错位 | 每人绑定独立素材与姓名单元 | 人数、顺序、身份逐一匹配 |
| 装饰好看但抢脸 | 降低脸周围细节与亮度，删次要道具 | 缩略图先识别人或所要求的主标题 |

身份错误、明显肢体错误、姓名错配、擅改确定文案属于否决项，不能由色彩或气氛得分抵消。方案阶段需检查提示词是否守住保留项；成图阶段还需目视核对，未生图不得报告“人物无畸变”。

## 9. 通用规则兼容与导入说明

保留单母体、统一世界观和有组织的拼贴。通用规则“表达体验优先使用人的动作和场景行为”在本类必须增加条件：“有指定人物照片时优先保留原动作，通过环境与图文关系表达体验；仅在 brief 允许时改动作”。否则模型可能为创意擅改姿态。

通用规则“生成顺序为结构→主体→场景→层级→元素→文案”建议同步改为“锁定人物与确定文案，先建立人物轮廓及文字占位，再完成场景与细节”。不要把前中后景变成每组必填。当前恰好三组、中文 imagePrompt、4—8组 sections 的接口保持不变。这里只指出兼容修改，不写回插件或用户已保存的规则快照。
